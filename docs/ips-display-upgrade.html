Hangar display — IPS upgrade

Migration cheat-sheet for swapping the original 3.2" MSP3218 panel for a 3.5" Haldzemo IPS (ST7796U + FT6336U capacitive). The whole upgrade is designed for one hangar visit and one reboot — pre-trip prep is done from your laptop, then the on-site work is just rewiring + power-on. Check off each step as you go; progress is saved per-browser.

Why we're upgrading

XPT2046 touch chip on the original board stopped responding on 2026-05-27 — display rendered fine but every diagnostic command returned all-zero MISO across 30+ samples. Pi-side SPI verified healthy (CE1 toggles correctly during transactions), both touch wires confirmed end-to-end with correct continuity, IC silkscreen confirmed XPT2046 — so the fault is on the display PCB side. Most likely a cold joint on Q1 (the NPN buffer between XPT2046's DOUT and the external SDO pad) or the chip itself. Reflowing fine-pitch SMD with the panel still attached needs hot-air gear; a $19 replacement that also gets us IPS was the right call.

Pre-trip prep (laptop work, before the display arrives)

None of this needs you at the hangar. The new code's already on the branch — you just need to enable I2C on the Pi and have python3-smbus installed so the post-swap boot is a clean cutover.

Power down before wiring

Important: shut the Pi cleanly before touching wires. The Pi's GPIO is not hot-pluggable, and a wiring slip with the Pi powered can fry both ends. This is doubly true here because VCC is moving from 3V3 to 5V — a slip lands 5V on a 3V3 signal pin if you're not careful.

Wiring — what moves

Only four wire positions change. Seven SPI/GND pins stay where they are. Read the table top-to-bottom; the silkscreen on the back of the new board lists pins 1-14 in this same order. When in doubt, the silkscreen wins.

# Display silkscreen Old Pi pin New Pi pin Notes
1 VCC 17 (3V3) 2 (5V) move ⟶ 5V Board spec is 5V; level shifters protect SPI signals.
2 GND 6 (or any GND) 6 (or any GND) same Pins 6 / 9 / 14 / 20 / 25 / 30 / 34 / 39 all work.
3 LCD_CS 24 (CE0) 24 (CE0) same SPI0 CE0 — display chip select.
4 LCD_RST 22 (BCM 25) 22 (BCM 25) same Display reset, driven by luma.lcd at init.
5 LCD_RS (= DC on the old board) 18 (BCM 24) 18 (BCM 24) same Data/command select. Function unchanged; silkscreen label is different.
6 MOSI 19 (BCM 10) 19 (BCM 10) same SPI MOSI.
7 SCK 23 (BCM 11) 23 (BCM 11) same SPI clock.
8 LED 17 (3V3) 2 (5V) move ⟶ 5V Backlight, always-on, 95 mA. Joins VCC on the 5V rail via splice / Y-pigtail.
9 MISO 21 (BCM 9) 21 (BCM 9) same SPI MISO. Display reads (init checks) use this; FT6336U doesn't.
10 CTP_SCL — 5 (BCM 3 / SCL1) new wire I2C clock for the touch chip. Pi's primary I2C bus.
11 CTP_RST (was T_CS on old) 26 (CE1) — pull old wire Old board had T_CS here, wired to Pi pin 26 for the XPT2046. New board's CTP_RST at the same header position stays unconnected (the FT6336U self-inits). So the existing wire that runs from this position to Pi 26 should be pulled at both ends, and Pi pin 26 stays empty.
12 CTP_SDA — 3 (BCM 2 / SDA1) new wire I2C data for the touch chip.
13 CTP_INT — — unconnected Touch interrupt. We poll at 20 Hz; no IRQ handler needed.
14 SD_CS — — unconnected microSD slot chip-select. Not used by this project.

Pi-side summary

Pi pinActionWas / is
2 (5V)2 wires addedWas empty. Now feeds both VCC (display pin 1) and LED (display pin 8).
17 (3V3)2 wires removedWas VCC + LED on the old display. Now only feeds the DS18B20 temp probe.
26 (CE1)1 wire removedWas the XPT2046's T_CS. FT6336U doesn't use SPI; pin freed.
3 (SDA1)1 wire addedI2C data to CTP_SDA (display pin 12).
5 (SCL1)1 wire addedI2C clock to CTP_SCL (display pin 10).
5V splitter pattern: Pi pin 2 needs to feed two display pins (VCC + LED). Cleanest: one F-F jumper from Pi pin 2 → display VCC, then a short male-male jumper from VCC over to LED on the display side. A breadboard rail or Y-pigtail off pin 2 also works.
Don't worry about CTP_INT / CTP_RST. Both are designed to float — the chip self-initialises and we poll for touches. Only wire CTP_RST if the very first power-on shows the chip not responding at all (extremely rare with these boards).

Wire verification

First light

Power the Pi back on and watch the journal for clean startup. The systemd unit auto-starts the display service.

If the display stays blank: see the troubleshooting section below. Most common cause is the wrong luma driver — if ili9488 doesn't produce an image, try ili9486 at the two references in display_loop.py.
If the image is rotated 90°: change rotate=0 to rotate=1 in display_loop.py:_open_device(). rotate=2 = 180° flip, rotate=3 = 270°.
If colours look inverted (whites are blue, etc.): the ST7796U might want bgr=True. Add that arg to the ili9488(...) constructor call.

Touch verification

Capacitive controllers report pre-calibrated pixel coords — no 4-corner walkthrough needed. Defaults in touch.py work out of the box for this board's chip orientation. We just need to confirm the chip is talking and the coords match the rendered button.

Only if taps don't register: run the I2C scan

Troubleshooting cheat-sheet

SymptomLikely causeFix
Display backlights but stays blank Wrong luma driver, or RESET wire not seated Try ili9486 in place of ili9488 in display_loop.py (two refs at line 86 + 93). Reseat the LCD_RST wire on display pin 4 → Pi pin 22.
Display dark, no backlight 5V not reaching LED Multimeter from Pi pin 2 → display pin 8 should read ~5V. Check the splitter / Y-pigtail.
Image rotated 90° / 180° MADCTL bits luma sets don't match this panel's orientation Change rotate=0 to 1, 2, or 3 in display_loop.py:_open_device().
Colours inverted (whites are blue) Panel is BGR, code expects RGB Add bgr=True to the ili9488(...) constructor call.
Service log: push failed: ImportError luma.lcd version doesn't have ili9488 sudo pip install --upgrade luma.lcd --break-system-packages
I2C scan finds no devices I2C not enabled, or wires on the wrong pads grep i2c /boot/firmware/config.txt should show dtparam=i2c_arm=on. ls /dev/i2c-* should show /dev/i2c-1. Verify SDA=Pi 3, SCL=Pi 5 on the display side too.
Service log: touch init failed: [Errno 2] /dev/i2c-1 missing Enable I2C: sudo raspi-config nonint do_i2c 0 && sudo reboot.
Service log: touch read failed: [Errno 121] Remote I/O error (one-off) I2C bus glitch One-off is fine. Persistent (every poll) → loose SDA/SCL contact, or missing pull-ups (add 4.7kΩ from each line to 3V3).
Heater toggle log appears but tap location feels wrong (button registers from outside the visible rect) Axes swap / invert config off Run --scan, tap each corner, compare to the table in "Touch verification". Set TOUCH_SWAP_XY / TOUCH_INVERT_X / TOUCH_INVERT_Y accordingly.
Display keeps restarting (systemd Restart=always kicking in) luma init crashing — usually missing controller class or wiring issue sudo journalctl -u display -n 50 for the stack trace. --once in dry-run mode bypasses SPI to isolate state-side bugs from hardware-side.
"updated Xm ago" stuck flashair-sync stopped writing the cache systemctl status flashair-sync
Heater toggles on its own (ghost taps) Stuck or wet finger on the panel Wipe the screen. Capacitive doesn't have a pressure threshold to raise — if it persists, the chip might be bad.

Rollback

If anything goes catastrophically wrong and you need to revert to the old MSP3218:

ssh pi
cd /usr/lib/cgi-bin/remote-switch
sudo -u leith git checkout main
sudo systemctl stop display
sudo shutdown -h now
# then physically swap the old display back in,
# reverse the four wiring changes (VCC/LED → pin 17, T_CS → pin 26,
# remove the SDA/SCL wires), and boot.

The old TOUCH_* keys (if not deleted) are still read by the rolled-back touch.py — different key names from the new I2C keys, so no conflict.
